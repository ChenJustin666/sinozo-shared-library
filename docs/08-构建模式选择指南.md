## 当前平台构建模式

### Java（当前实现）
- **构建位置**：Jenkins节点（宿主机构建）
- **流程**：
  ```
  1. Jenkins节点执行 mvn clean package
  2. 生成 target/app.jar
  3. Dockerfile 只做运行镜像打包（单阶段）
  ```
- **Dockerfile**：
  ```dockerfile
  FROM eclipse-temurin:17-jre-alpine
  COPY target/app.jar app.jar  # ← 依赖Jenkins已构建的jar
  ENTRYPOINT ["java", "-jar", "app.jar"]
  ```

### Node.js（当前实现）
- **构建位置**：Docker内（多阶段构建）
- **流程**：
  ```
  1. Jenkins触发 docker build
  2. Docker内执行 npm ci && npm run build
  3. 多阶段打包运行镜像
  ```
- **Dockerfile**：
  ```dockerfile
  FROM node:20-alpine AS builder
  RUN npm ci && npm run build
  
  FROM node:20-alpine
  COPY --from=builder /app /app
  CMD ["pm2-runtime", "npm", "--", "start"]
  ```

## 推荐方案

### ✅ 默认：Docker内构建（推荐）

**核心理念**：**Dockerfile = 可移植的构建文档**

#### 优势

1. **环境一致性** 🎯
   ```
   开发机 docker build  ==  Jenkins docker build  ==  任何CI平台
   ```
   - 消除"在我机器上能跑"问题
   - 新人入职零配置，只需Docker

2. **平台无关性** 🚀
   - 不依赖Jenkins节点的JDK/Maven/Python版本
   - 轻松迁移到GitLab CI / GitHub Actions / Tekton
   - 本地调试与CI完全一致

3. **Docker缓存优化** ⚡
   ```dockerfile
   # 依赖层单独缓存
   COPY pom.xml .
   RUN mvn dependency:go-offline  # ← 这层只在pom.xml改变时重新执行
   
   COPY src/ ./src/
   RUN mvn package                # ← 只在代码改变时重新编译
   ```

4. **安全隔离** 🔒
   - 构建在容器内完成，不污染Jenkins节点
   - 依赖下载受Dockerfile控制，可审计

5. **现代化最佳实践** 📦
   - Kubernetes原生应用标准
   - 支持Cloud Native Buildpacks
   - GitOps友好

#### 适用场景
- ✅ 新项目（**强烈推荐**）
- ✅ Python/Go/Rust等无重量级缓存的语言
- ✅ 前端项目（Node.js/Vue/React）
- ✅ 需要跨平台构建的服务
- ✅ 微服务架构（统一构建流程）

---

### 🔄 保留能力：宿主机构建（特殊场景）

**仅在以下情况使用**：

#### 适用场景

1. **Maven依赖巨大且频繁变化**
   - Jenkins节点 `/home/jenkins/.m2/repository` 缓存数GB
   - Docker Layer Cache在频繁依赖更新时效率低

2. **企业内网限制**
   - 容器内无法访问企业Maven私服
   - Jenkins节点已配置好企业 `settings.xml`

3. **遗留项目兼容**
   - 大量存量Java项目已使用宿主机构建
   - 短期内无精力迁移

4. **特殊构建工具**
   - 使用Jenkins特有插件（如SonarQube Scanner）
   - 需要访问Jenkins凭据（在Dockerfile外）

#### 劣势
- ❌ 依赖Jenkins节点环境配置
- ❌ 本地无法复现CI构建
- ❌ 难以迁移到其他CI平台
- ❌ Jenkins节点需维护多版本JDK/Maven

## 各语言最佳实践

### Java

#### 推荐：Docker内多阶段构建

```dockerfile
# ============================================================
# Java 17 Spring Boot 多阶段构建（推荐）
# 构建方式：Docker内完整构建，Jenkins只负责 docker build
# ============================================================
FROM maven:3.9-eclipse-temurin-17-alpine AS builder

WORKDIR /app

# 1. 先复制pom.xml，利用Docker缓存
COPY pom.xml .
RUN mvn dependency:go-offline -B

# 2. 复制源码并编译
COPY src ./src
RUN mvn clean package -DskipTests -B && \
    mv target/*.jar target/app.jar

# 运行阶段（精简镜像）
FROM eclipse-temurin:17-jre-alpine

RUN apk add --no-cache curl tzdata && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone && \
    apk del tzdata && \
    addgroup -S appgroup && adduser -S appuser -G appgroup

WORKDIR /app
COPY --from=builder /app/target/app.jar app.jar
RUN chown appuser:appgroup app.jar

USER appuser

ENV JAVA_OPTS="" \
    TZ=Asia/Shanghai

EXPOSE 8080

ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar app.jar"]
```

**Jenkinsfile配置**：
```groovy
@Library('k8s-deploy-lib@main') _
k8sDeploy(
    projectName:  'myproject',
    serviceName:  'my-service',
    serviceType:  'java',
    buildMode:    'docker',  // ← 新参数：docker内构建
    dockerImage:  'my-service',
    dockerCredId: 'docker-swr-cred',
)
```

#### 保留：宿主机构建（存量兼容）

**当前Dockerfile**（保持不变）：
```dockerfile
FROM eclipse-temurin:17-jre-alpine
COPY target/app.jar app.jar  # ← Jenkins已构建
ENTRYPOINT ["java", "-jar", "app.jar"]
```

**Jenkinsfile配置**：
```groovy
k8sDeploy(
    buildMode:    'host',  // ← 显式指定宿主机构建
    jdkTool:      'jdk 17',
    mavenGoals:   'clean package -DskipTests',
)
```

### Python

#### 推荐：Docker内多阶段构建

```dockerfile
# ============================================================
# Python FastAPI/Flask 多阶段构建
# 构建方式：Docker内构建，Jenkins只负责 docker build
# ============================================================
FROM python:3.11-slim AS builder

WORKDIR /app

# 安装依赖到用户目录
COPY requirements.txt .
RUN pip install --user --no-cache-dir -r requirements.txt

# 复制代码
COPY . .

# 运行阶段
FROM python:3.11-slim

RUN apt-get update && apt-get install -y tzdata && \
    ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    rm -rf /var/lib/apt/lists/* && \
    addgroup --system appgroup && adduser --system --ingroup appgroup appuser

WORKDIR /app

# 从构建阶段复制依赖和代码
COPY --from=builder /root/.local /root/.local
COPY --from=builder /app /app

RUN chown -R appuser:appgroup /app

USER appuser

ENV PATH=/root/.local/bin:$PATH \
    PYTHONUNBUFFERED=1 \
    TZ=Asia/Shanghai

EXPOSE 8080

# 根据框架选择启动方式
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
# 或 gunicorn: CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:8080", "main:app"]
```

**Jenkinsfile配置**：
```groovy
k8sDeploy(
    serviceType:  'python',  // ← 需要在共享库添加支持
    buildMode:    'docker',
    dockerImage:  'my-python-api',
)
```

### Go

#### 推荐：Docker内多阶段构建（静态二进制）

```dockerfile
# ============================================================
# Go 多阶段构建（极致精简）
# 构建方式：Docker内构建，Jenkins只负责 docker build
# 最终镜像：alpine ~10MB（甚至可以用 scratch）
# ============================================================
FROM golang:1.21-alpine AS builder

WORKDIR /app

# 利用go.mod缓存
COPY go.mod go.sum ./
RUN go mod download

# 编译静态二进制
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -ldflags="-w -s" -o main .

# 运行阶段（极致精简）
FROM alpine:3.19

RUN apk add --no-cache ca-certificates tzdata && \
    cp /usr/share/zoneinfo/Asia/Shanghai /etc/localtime && \
    echo "Asia/Shanghai" > /etc/timezone && \
    apk del tzdata && \
    addgroup -S appgroup && adduser -S appuser -G appgroup

WORKDIR /app

COPY --from=builder /app/main .
RUN chown appuser:appgroup main

USER appuser

ENV TZ=Asia/Shanghai

EXPOSE 8080

ENTRYPOINT ["./main"]
```

**Jenkinsfile配置**：
```groovy
k8sDeploy(
    serviceType:  'go',
    buildMode:    'docker',
    dockerImage:  'my-go-service',
)
```

### Node.js（已实现，保持不变）

**当前Docker内构建已是最佳实践**，无需调整：

```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app

RUN npm ci
COPY . .
```

#### 2. 修改 `buildAndPush()` 函数

**在 `k8sDeploy.groovy` 第785行修改**：

```groovy
def buildAndPush(Map cfg) {
    // 根据 buildMode 决定构建方式
    if (cfg.buildMode == 'host') {
        // 宿主机构建（存量兼容）
        if (cfg.serviceType == 'java') {
            buildJava(cfg)  // Jenkins节点执行Maven
        } else if (cfg.serviceType == 'nodejs') {
            buildNodejs(cfg)  // 预检查
        } else if (cfg.serviceType == 'python') {
            buildPython(cfg)  // 预检查
        } else if (cfg.serviceType == 'go') {
            buildGo(cfg)  // 预检查
        }
    } else {
        // Docker内构建（默认，推荐）
        echo "🐳 使用Docker内多阶段构建"
        // 直接跳到 pushImage，构建在Dockerfile内完成
    }

    // 推送镜像
    def originalProject = env.IMAGE_PROJECT
    env.IMAGE_PROJECT = env.IMAGE_PROJECT_BUILD
    try {
        pushImage(cfg)
    } finally {
        env.IMAGE_PROJECT = originalProject
    }
}
```

```groovy
def findDockerfile(Map config) {
    // 优先使用业务仓库的Dockerfile
    if (fileExists('Dockerfile')) {
        echo "📄 使用业务仓库 Dockerfile"
        return 'Dockerfile'
    }

    // Fallback到模板（主要用于初始化新项目）
    def baseDir = env.DEPLOY_BASE_DIR
    def templateMap = [
        'java':    config.jdkTool?.toLowerCase()?.contains('17') ? 
                   'Dockerfile.java17' : 'Dockerfile.java8',
        'nodejs':  'Dockerfile.nodejs-pm2',
        'python':  'Dockerfile.python',
        'go':      'Dockerfile.go',
    ]
    
    def templateName = templateMap[config.serviceType]
    if (templateName) {
        def tpl = "${baseDir}/shared-library/templates/${templateName}"
        if (fileExists(tpl)) {
            echo "📄 使用平台模板: ${templateName}"
            return tpl
        }
    }

    error "❌ 找不到 Dockerfile，serviceType: ${config.serviceType}"
}
```

## 迁移路径

### 阶段1：新项目默认Docker内构建（立即实施）

1. ✅ 所有新Java项目使用多阶段Dockerfile
2. ✅ Python/Go新项目从一开始使用Docker内构建
3. ✅ 初始化脚本默认生成Docker模式配置

### 阶段2：存量项目逐步迁移（3-6个月）

**迁移步骤**（单个服务）：

```bash
# 1. 在业务仓库创建多阶段Dockerfile
cp Dockerfile Dockerfile.old
# 使用新模板替换

# 2. 本地验证
docker build -t my-service:test .
docker run -p 8080:8080 my-service:test

# 3. 更新Jenkinsfile
k8sDeploy(
    buildMode: 'docker',  # host → docker
    # 移除 jdkTool/mavenGoals（Docker内构建不需要）
)

# 4. 测试环境验证
# 触发test Job，观察构建日志

# 5. 生产环境同步
# 将测试通过的 commit 合并到 PROD_BRANCH（例如 master），生产 Job 复用同一镜像
```

**迁移优先级**：
1. 🟢 高 - 新开发的微服务
2. 🟡 中 - 频繁迭代的业务服务
3. 🔴 低 - 稳定运行的遗留系统（不强制迁移）

### 阶段3：完全标准化（6-12个月后）

- 📚 文档明确推荐Docker内构建
- 🏗️ 宿主机构建标记为"遗留模式"
- 🎓 新员工培训只介绍Docker模式

## 总结

### 推荐策略

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| **新Java项目** | Docker内构建 | 现代化、可移植 |
| **存量Java项目** | 可选迁移 | 非强制，逐步过渡 |
| **Python/Go新项目** | Docker内构建 | 唯一支持模式 |
| **Node.js** | Docker内构建 | 当前标准，不变 |
| **企业内网受限** | 宿主机构建 | 容器内无法访问私服 |

### 核心原则

1. **新项目优先Docker内构建** - 从源头建立标准
2. **存量项目保持兼容** - 不强制迁移，避免风险
3. **文档优先推荐Docker** - 引导开发者采用最佳实践
4. **平台提供双模式支持** - 满足不同场景需求

### 关键优势

- ✅ **环境一致性**：本地 = CI = 生产
- ✅ **平台无关性**：轻松迁移CI工具
- ✅ **新人友好**：零配置上手
- ✅ **安全隔离**：构建在容器内
- ✅ **现代化**：符合云原生标准

### 镜像大小对比

| 语言 | 构建方式 | 运行镜像大小 |
|------|---------|-------------|
| Java | Docker多阶段 | ~200MB (JRE) |
| Python | Docker多阶段 | ~100-150MB |
| Go | Docker多阶段 | ~10-20MB (alpine) |
| Node.js | Docker多阶段 | ~150MB |

**最终目标**：让Dockerfile成为应用构建的唯一真相来源（Single Source of Truth）。
