## 二、核心标准

### 2.1 配置标准

| 项目 | 标准 | 理由 |
|------|------|------|
| **配置位置** | 全部在 k8s-deploy 仓库 | 统一管理、权限控制、版本追溯 |
| **配置方式** | 全部接入 Nacos | 标准统一、动态刷新、多环境管理 |
| **Git 管理** | 所有配置必须提交 Git | 版本控制、可回滚、有审计 |
| **镜像 Tag** | 自动生成（R{commit}） | Jenkins 自动处理，不需要手工改 |

### 2.2 权限标准

| 操作 | 开发 | 测试 | 运维 |
|------|------|------|------|
| 改 Nacos 配置（dev/test） | ✅ | ✅ | ✅ |
| 改 Nacos 配置（prod） | ❌ | ❌ | ✅ |
| 改 values（dev/test） | ✅ MR | ✅ MR | ✅ |
| 改 values（prod） | ❌ | ❌ | ✅ |
| 部署 dev/test | ✅ | ✅ | ✅ |
| 部署 prod | ❌ | ❌ | ✅ |
| 回滚 | ❌ | ✅ | ✅ |

## 三、新服务上线流程

### Step 1：运维初始化（5 分钟）

```bash
cd k8s-deploy

# 1. 运行初始化脚本
./automation/init-service.sh adv new-service java

# 2. 生成文件：
#    - projects/adv/dev/new-service/values-dev.yaml
#    - projects/adv/test/new-service/values-test.yaml
#    - projects/adv/prod/new-service/values-prod.yaml
#    - /tmp/new-service-init/Dockerfile
#    - /tmp/new-service-init/Jenkinsfile

# 3. 提交配置
git add projects/adv/
git commit -m "feat: 添加 new-service 配置"
git push

# 4. 通知开发复制文件
```

### Step 2：开发接入（10 分钟）

```bash
# 1. 复制文件到业务仓库
cp /tmp/new-service-init/Dockerfile 业务仓库/
cp /tmp/new-service-init/Jenkinsfile 业务仓库/

# 2. 接入 Nacos（如果还没接入）
#    - 添加 Nacos 依赖
#    - 配置搬到 Nacos 控制台
#    - 本地验证

# 3. 提交代码
git add Dockerfile Jenkinsfile
git commit -m "feat: 容器化配置"
git push
```

### Step 3：运维创建 Jenkins Job（5 分钟）

```
Jenkins → New Item → Pipeline
  Name: new-service-test
  Pipeline script from SCM:
    Git: 业务仓库地址
    Script Path: Jenkinsfile
  Parameters:
    DEPLOY_ENV: test（默认值）
```

### Step 4：首次部署（3-5 分钟）

```
Jenkins → new-service-test → Build with Parameters
  DEPLOY_ENV: test
  ACTION: deploy
  → Build Now
```

**总耗时：20-25 分钟**

## 四、日常操作

### 4.1 改业务配置（开发自主，1 分钟）

```
Nacos 控制台 → 找到配置 → 修改 → 发布 → 服务自动刷新
```

### 4.2 改基础设施配置（开发提 MR，10-15 分钟）

```bash
# 1. Fork k8s-deploy 仓库
git clone git@git.com:ops/k8s-deploy.git

# 2. 改配置
vim projects/adv/test/ad-gateway/values-test.yaml

# 3. 提交 MR
git add projects/adv/test/ad-gateway/values-test.yaml
git commit -m "feat: 调整内存"
git push

# 4. 创建 Merge Request

# 5. 自动检查 + 自动 merge（测试环境）

# 6. Jenkins 自动部署
```

### 4.3 部署新版本（开发触发，3-5 分钟）

```
Jenkins → ad-gateway-test → Build with Parameters
  ACTION: deploy
  → Build Now
```

### 4.4 重启服务（开发/运维，30 秒）

```
Jenkins → ad-gateway-test → Build with Parameters
  ACTION: restart
  → Build Now
```

### 4.5 回滚（运维，1 分钟）

```
Jenkins → ad-gateway-prod → Build with Parameters
  ACTION: rollback
  ROLLBACK_REVISION: 0（上一个版本）
  → Build Now
```

## 五、多集群管理

### 5.1 集群命名规范

```
Jenkins Credentials ID:
  k8s-cn-beijing-test      # 北京测试集群
  k8s-cn-shanghai-test     # 上海测试集群
  k8s-cn-beijing-prod      # 北京生产集群
  k8s-cn-shanghai-prod     # 上海生产集群
  k8s-us-west-prod         # 美西生产集群
```

### 5.2 部署到指定集群

```
Jenkins → ad-gateway-prod → Build with Parameters
  DEPLOY_ENV: prod
  DEPLOY_CLUSTER: cn-beijing（选择集群）
  → Build Now
```

### 5.3 批量部署（运维操作）

```bash
cd k8s-deploy
python automation/batch-deploy.py \
  --service ad-gateway \
  --clusters cn-beijing,cn-shanghai,us-west \
  --canary  # 灰度发布
```

```

  ↓
Prometheus 中心 → 汇总所有集群
  ↓

```
Kibana → 搜索
  service: ad-gateway
  cluster: cn-beijing-prod

## 七、故障处理

### 7.1 服务启动失败

```bash
# 1. 查看 Pod 状态
kubectl get pods -n adv-test

# 2. 查看日志
kubectl logs -f deployment/ad-gateway -n adv-test

# 3. 查看事件
kubectl describe pod ad-gateway-xxx -n adv-test

# 4. 常见问题：
#    - 镜像拉取失败 → 检查镜像仓库凭据
#    - 启动超时 → 检查 Startup Probe 配置
#    - OOM → 增加内存限制
```

### 7.2 配置错误

```bash
# 1. 查看当前配置
helm get values ad-gateway -n adv-test

# 2. 回滚到上一个版本
helm rollback ad-gateway -n adv-test

# 3. 或者修改配置重新部署
vim projects/adv/test/ad-gateway/values-test.yaml
git commit && git push
# Jenkins 自动部署
```

### 7.3 紧急回滚

```
Jenkins → ad-gateway-prod → Build with Parameters
  ACTION: rollback
  ROLLBACK_REVISION: 0
  → Build Now
```

## 八、最佳实践

### 8.1 发布策略

```
开发环境：自动部署（push 即部署）
测试环境：手动触发（测试验证后）
生产环境：灰度发布（金丝雀 → 全量）
```

### 8.2 资源配置

```yaml
# 开发环境：资源少
resources:
  limits:
    cpu: "500m"
    memory: 512Mi

# 测试环境：中等资源
resources:
  limits:
    cpu: "1"
    memory: 1Gi

# 生产环境：高资源 + HPA
resources:
  limits:
    cpu: "2"
    memory: 2Gi
hpa:
  enabled: true
  minReplicas: 3
  maxReplicas: 10
```

### 8.3 配置管理

```
经常变的配置 → Nacos（数据库、Redis、业务开关）
不常变的配置 → values.yaml（CPU、内存、副本数）
密钥 → Jenkins Credentials（Nacos 密码、镜像仓库密码）
```
