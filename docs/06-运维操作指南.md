# 运维操作指南

> 本文档面向**运维 / 平台工程师**，涵盖：Jenkins 环境搭建、新服务上线审批、生产配置管理、日常巡检与故障处理。

---

## 一、运维职责边界

| 操作 | Owner | 说明 |
|------|-------|------|
| Jenkins 全局配置（共享库、凭据、工具） | 运维 | 一次配置，全局生效 |
| `baselines/_global.yaml` | 运维 | 全局镜像仓库、默认资源等 |
| `baselines/projects/<proj>/_overrides.yaml` | 运维 | 项目级 namespace / SWR project 覆盖 |
| `baselines/projects/<proj>/<svc>/values-prod.yaml` | 运维 | 生产配置，开发无 push 权限 |
| prod 部署触发 | 运维 | DEVOPS_USERS 白名单控制 |
| 回滚 / 重启 | 运维 | 任何时候可操作 |
| `deploy/values-test.yaml` | 开发 | 运维无需介入 |
| Dockerfile / Jenkinsfile | 开发 | 运维无需介入 |

## 二、Jenkins 环境搭建（一次性）

### 2.1 安装必要插件

在 Jenkins 插件管理中安装：

- `Pipeline`（流水线基础）
- `Git Parameter`（支持分支/Tag 选择参数）
- `Credentials Binding`（凭据绑定）
- `Docker Pipeline`（Docker 命令支持）

### 2.2 配置全局共享库

Manage Jenkins → System → Global Pipeline Libraries → Add

```
Name:            k8s-deploy-lib
Default Version: main
Source:          Modern SCM → Git
URL:             https://github.com/ChenJustin666/sinozo-shared-library.git
Credentials:     <选择 github-token-justin 凭据>
```

> 配置后，业务 Jenkinsfile 中的 `@Library('k8s-deploy-lib@main') _` 才能生效。

### 2.3 配置全局环境变量

Manage Jenkins → System → Global properties → Environment variables

```
K8S_DEPLOY_LIB_URL     = https://github.com/ChenJustin666/sinozo-shared-library.git
K8S_DEPLOY_LIB_CRED    = github-token-justin
K8S_DEPLOY_LIB_BRANCH  = main
DEVOPS_USERS           = admin,shengqun          # prod 触发白名单
BUILD_AGENT_LABEL      = k8s-build               # 可选，默认构建节点标签
```

> 如果使用全局变量配置 kubeconfig，还可以加：
> ```
> K8S_CRED_TEST = test-k8s-cluster
> K8S_CRED_PROD = prod-k8s-cluster
> ```
> 这样业务 Jenkinsfile 里就不需要写 `kubeconfigCredId`。

### 2.4 配置 Jenkins 凭据

Manage Jenkins → Credentials → System → Global credentials → Add Credentials

| 凭据 ID | 类型 | 获取方式 |
|---------|------|---------|
| `docker-swr-cred` | Username with password | 华为云 IAM → 访问密钥（AK=用户名，SK=密码） |
| `github-token-justin` | Username with password | GitHub → Settings → Developer settings → Tokens |
| `test-k8s-cluster` | Secret file | 阿里云/华为云 K8s 控制台下载 kubeconfig，上传文件 |
| `prod-k8s-cluster` | Secret file | 同上，prod 集群 |
| `nacos-adv-cred` | Username with password | Nacos 控制台账号（如业务使用） |

### 2.5 配置 Jenkins 工具

Manage Jenkins → Tools

**JDK 配置**：
- Name: `jdk 1.8`（需与业务 Jenkinsfile 中 `jdkTool` 一致）
- JAVA_HOME: JDK 安装路径，或从 Oracle/AdoptOpenJDK 自动安装

**Maven 配置**：
- Name: `Maven 3.8.8`
- 或留空，节点上 `/usr/local/maven` 会自动使用

### 2.6 Jenkins Agent 节点要求

Agent 节点需要预装：
- Docker（用于镜像构建和推送）
- `sudo /usr/local/bin/helm`（Helm 3）
- `sudo /usr/local/bin/kubectl`（kubectl，可选，Helm 会自动用它检查 namespace）
- Git
- Python3 + PyYAML（`pip3 install pyyaml`，用于 YAML 解析，否则 fallback 到 awk）

## 三、新服务上线审批流程

### 3.1 收到开发申请后

```bash
# 克隆运维仓库到本地
git clone https://github.com/ChenJustin666/sinozo-shared-library.git
cd sinozo-shared-library

# 运行初始化脚本（同时生成业务文件模板 + prod 占位）
./automation/init-service.sh <project> <service> [java|nodejs]

# 示例
./automation/init-service.sh adv ad-gateway java
```

### 3.2 review prod 配置

脚本在本地生成了 `baselines/projects/<project>/<service>/values-prod.yaml`，**必须 review 以下字段**：

```yaml
# baselines/projects/<project>/<service>/values-prod.yaml

service:
  port: 8080       # ✅ 确认端口与开发对齐
  replicas: 2      # ⚠️ 生产建议 ≥ 2，默认生成是 1 要改

resources:
  enabled: true
  requests:
    cpu: 500m       # 按压测结果填
    memory: 1Gi
  limits:
    cpu: 2000m      # ⚠️ 必须填，防止无限占资源
    memory: 4Gi     # ⚠️ 必须 ≥ java -Xmx 值

java:
  enabled: true
  opts: >-
    -Dspring.profiles.active=prod
    -DNACOS_SERVERS=nacos-prod.internal:8848    # ⚠️ 改成 prod 地址
    -DNACOS_NAMESPACE=prod_namespace
    -Xms2g -Xmx4g                              # ⚠️ 改大，小于 limits.memory

env:
  - name: LOG_LEVEL
    value: info          # ⚠️ prod 改成 info，不要 debug

# 关键服务建议开启 HPA + PDB：
hpa:
  enabled: true          # prod 流量大的服务建议开
  minReplicas: 2
  maxReplicas: 10
  cpuTarget: 70

pdb:
  enabled: true          # 有多副本的服务建议开，防止 K8s 维护时同时驱逐所有 pod
  minAvailable: 1

# 多副本互斥（防止所有副本在同一节点）：
affinity:
  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app: ad-gateway
          topologyKey: kubernetes.io/hostname
```

### 3.3 push 到运维仓库

```bash
cd sinozo-shared-library

git add baselines/projects/<project>/<service>/values-prod.yaml
git commit -m "ops: <service> prod 配置 - 首次接入 review"
git push origin main
```

### 3.4 通知开发创建 Jenkins Job

告知开发：
1. 将脚本生成的 `Dockerfile`、`Jenkinsfile`、`deploy/values-test.yaml` 复制到业务仓库
2. 修改 Jenkinsfile 中的 `kubeconfigCredId`（凭据 ID 由运维提供）
3. 修改 `deploy/values-test.yaml` 中 Nacos 地址、端口等
4. 在 Jenkins 创建 Pipeline Job，指向业务仓库 Jenkinsfile

## 四、全局基线管理

### 4.1 _global.yaml 结构说明

```yaml
# baselines/_global.yaml

# SWR 镜像仓库地址
image:
  registry: swr.ap-southeast-3.myhuaweicloud.com

  # 各环境对应的 SWR Organization
  # ⚠️ dev 和 test 必须用同一个（test 会找 dev 构建的镜像）
  projects:
    dev:  sinozo-test
    test: sinozo-test
    prod: sinozo-prod

  pullSecret: regcred
  pullPolicy: IfNotPresent

# 零停机滚动更新策略（所有服务共用）
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0

# 默认资源（极低值，具体值在业务 values 里写）
resources:
  enabled: true
  requests:
    cpu: 100m
    memory: 256Mi
```

### 4.2 修改全局镜像仓库地址

```bash
vi baselines/_global.yaml
# 修改 image.registry

git add baselines/_global.yaml
git commit -m "ops: 更新 SWR 镜像仓库地址"
git push origin main
```

更新后，下次所有服务部署时自动生效（Pipeline 自动 git pull 运维仓库）。

### 4.3 项目级覆盖（_overrides.yaml）

当某个项目的 namespace 命名或 SWR project 与全局不同时，创建项目级覆盖：

```yaml
# baselines/projects/<project>/_overrides.yaml

# 覆盖 namespace 命名（默认是 {project}-{env}）
namespaces:
  test: adv-ops-test      # 如 adv 项目 test 集群的 namespace 不叫 adv-test
  prod: adv-ops-prod

# 覆盖该项目使用的 SWR project（不写则继承 _global.yaml）
image:
  projects:
    test: sinozo-test
    prod: adv-prod         # adv 项目 prod 镜像放在专属 SWR organization
```

## 五、生产配置变更流程

### 5.1 修改 prod 配置（如调整资源、JVM 参数）

```bash
cd sinozo-shared-library

# 编辑目标服务的 prod 配置
vi baselines/projects/<project>/<service>/values-prod.yaml

# review 后 push
git add baselines/projects/<project>/<service>/values-prod.yaml
git commit -m "ops: <service> 调整 prod 资源 - CPU limits 2C→4C"
git push origin main
```

然后在 Jenkins 重新触发 prod Job（`ACTION=deploy`），Helm 会 rolling update。

### 5.2 prod 探针从 tcp 切换到 http

在 `values-prod.yaml` 中：

```yaml
probes:
  enabled: true
  type: http              # 从 tcp 切换到 http
  path: /actuator/health  # 确认接口实际存在且返回 200
  port: 8080
  liveness:
    periodSeconds: 10
    failureThreshold: 3
  readiness:
    periodSeconds: 5
    failureThreshold: 3
  startup:
    periodSeconds: 10
    failureThreshold: 30   # 5 分钟启动窗口
```

> ⚠️ 生产切 http 探针风险高，切前先确认接口在 test 稳定。

## 六、日常运维操作

### 6.1 查看 Helm Release 状态

```bash
# 列出所有 release
helm list -n <project>-prod

# 查看 release 详情
helm status <service> -n <project>-prod

# 查看历史版本
helm history <service> -n <project>-prod
```

### 6.2 回滚

Jenkins Job → Build with Parameters：
```
ACTION = rollback
ROLLBACK_REVISION = 0    （0=上一版本，具体版本号从 helm history 查）
```

也可直接命令行：
```bash
helm rollback <service> [revision] -n <project>-prod
```

### 6.3 紧急重启（不重新部署）

Jenkins Job → Build with Parameters：
```
ACTION = restart
```

等同于：
```bash
kubectl rollout restart deployment/<service> -n <project>-prod
```

### 6.4 查看部署预览备份

Pipeline 每次部署前会把完整 helm template 渲染结果备份到 Jenkins Agent：
```bash
# 在 Jenkins agent 节点
ls ~/.deploy-previews/prod/<service>-*.yaml

# 查看最近一次渲染结果
cat ~/.deploy-previews/prod/<service>-R1a2b3c4d-20260528120000.yaml

# 30 天自动清理，不用手动维护
```

### 6.5 手工验证 values 合并结果

在 Jenkins agent 上，可以手动运行 helm template 查看渲染结果：

```bash
cd /path/to/sinozo-shared-library

helm template <service> charts/generic-service \
  -f baselines/_global.yaml \
  -f baselines/projects/<project>/_overrides.yaml \   # 如果存在
  -f baselines/projects/<project>/<service>/values-prod.yaml \
  --set image.tag=R1a2b3c4d \
  --set service.name=<service> \
  --set service.namespace=<project>-prod
```

## 七、prod 首次部署自动生成模板处理

当某服务首次部署 prod 且运维仓库没有 `values-prod.yaml` 时，Pipeline 会：

1. **自动从 `deploy/values-test.yaml` 生成模板**，写入 `baselines/projects/<proj>/<svc>/values-prod.yaml`
2. **尝试 git push** 到运维仓库（使用 `K8S_DEPLOY_LIB_CRED`）
3. **本次部署 fail**（必须等运维 review 后重新触发）

**运维处理步骤**：

```bash
# 1. 检查自动 push 是否成功
cd sinozo-shared-library
git fetch origin main
git log --oneline origin/main | head -5
# 看到 "[ci-auto] <svc>: 自动生成 prod values 模板" 说明 push 成功

# 2. 如果没看到（push 失败），从 Jenkins console 复制文件内容手工创建
mkdir -p baselines/projects/<project>/<service>/
vi baselines/projects/<project>/<service>/values-prod.yaml
# 粘贴 console 中打印的完整内容

# 3. review 必改字段（参考第三章 3.2 节）
vi baselines/projects/<project>/<service>/values-prod.yaml

# 4. push
git pull --rebase origin main
git add baselines/projects/<project>/<service>/
git commit -m "ops: <service> prod 配置 review"
git push origin main

# 5. 重新触发 Jenkins prod Job
```

## 八、权限管理

### 8.1 prod 触发权限

在 Jenkins 全局环境变量 `DEVOPS_USERS` 中维护：

```
DEVOPS_USERS = admin,shengqun,ops-zhang
```

只有白名单中的用户才能触发 prod 部署（`checkPermission.groovy` 检查 `currentBuild.rawBuild` 的触发者）。

添加/删除用户：Manage Jenkins → System → Global properties → 修改 DEVOPS_USERS → 保存。

### 8.2 开发无法访问 prod 配置

确保开发人员没有运维仓库的 push 权限（`baselines/` 目录）。

Git 仓库建议配置分支保护：
- `main` 分支：仅运维账号可直接 push
- 业务仓库：开发有完整权限，运维不干涉

## 九、新增项目

当公司新建一个项目（如 `bigdata`），需要：

1. **在 `baselines/_global.yaml` 确认** `image.projects` 是否已包含对应环境（通常全局配置已够）

2. **如有 namespace 特殊命名**，创建项目级覆盖：
   ```bash
   mkdir -p baselines/projects/bigdata
   cat > baselines/projects/bigdata/_overrides.yaml <<EOF
   # 如果 namespace 命名不是默认的 bigdata-test / bigdata-prod
   namespaces:
     test: bigdata-app-test
     prod: bigdata-app-prod
   EOF
   
   git add baselines/projects/bigdata/
   git commit -m "ops: bigdata 项目初始化 - 自定义 namespace"
   git push origin main
   ```

3. **为新项目各服务分别运行** `init-service.sh`

## 十、故障排查手册

### 10.1 Pod 未 Running，查看日志

```bash
# 查看 pod 状态
kubectl get pods -n <project>-prod

# 查看 pod 详情（Events 里有报错原因）
kubectl describe pod <pod-name> -n <project>-prod

# 查看容器日志
kubectl logs <pod-name> -n <project>-prod --tail=100

# 查看上一次崩溃的日志
kubectl logs <pod-name> -n <project>-prod --previous
```

### 10.2 Helm 部署卡住（--wait 超时）

```bash
# 查看 helm release 状态
helm status <service> -n <project>-prod

# 强制终止卡住的 deployment rollout
kubectl rollout undo deployment/<service> -n <project>-prod

# 或直接回滚到上一版本
helm rollback <service> 0 -n <project>-prod
```

### 10.3 镜像拉取失败（ImagePullBackOff）

```bash
# 检查 regcred secret 是否存在且未过期
kubectl get secret regcred -n <project>-prod
kubectl describe secret regcred -n <project>-prod

# 手动重建 regcred（临时修复，下次部署时 Helm 会自动 reconcile）
kubectl delete secret regcred -n <project>-prod
kubectl create secret docker-registry regcred \
  --docker-server=swr.ap-southeast-3.myhuaweicloud.com \
  --docker-username=<AK> \
  --docker-password=<SK> \
  -n <project>-prod
```

### 10.4 Helm 报 "cannot import" 错误

```
Error: INSTALLATION FAILED: rendered manifests contain a resource that already exists.
Unable to continue with install: Secret "regcred" in namespace "xxx" exists and cannot be imported: missing key "meta.helm.sh/release-name"
```

**原因**：命名空间中有手工创建的同名资源，没有 Helm 管理标签。

**解决**：Pipeline 的 `adoptExistingResource` 函数会自动处理，直接重新触发 Job 即可。如果问题持续，手工添加标签：

```bash
kubectl label secret regcred -n <project>-prod app.kubernetes.io/managed-by=Helm --overwrite
kubectl annotate secret regcred -n <project>-prod \
  meta.helm.sh/release-name=<service> \
  meta.helm.sh/release-namespace=<project>-prod --overwrite
```

### 10.5 values 合并后配置不符合预期

检查 values 文件的加载顺序（后面覆盖前面）：

```
① charts/generic-service/values.yaml   （最低优先级）
② baselines/_global.yaml
③ baselines/projects/<proj>/_overrides.yaml
④ deploy/values.yaml
⑤ deploy/values-test.yaml  或  baselines/projects/<proj>/<svc>/values-prod.yaml
⑥ --set（最高优先级，CI 注入）
```

用 `helm template` 手工验证（见 6.5 节）。

### 10.6 Image Promotion 失败

```bash
# 手工执行 promotion（生产紧急情况）
docker login swr.ap-southeast-3.myhuaweicloud.com -u <AK> -p <SK>
docker pull swr.ap-southeast-3.myhuaweicloud.com/sinozo-test/<service>:<tag>
docker tag swr.../sinozo-test/<service>:<tag> swr.../sinozo-prod/<service>:<tag>
docker push swr.ap-southeast-3.myhuaweicloud.com/sinozo-prod/<service>:<tag>
```

然后重新触发 prod Job，或使用 `IMAGE_TAG` 参数指定已 promotion 完的 tag。

## 十一、安全加固建议

1. **Jenkins agent 隔离**：prod 集群 kubeconfig 只存 Jenkins，不放到 agent 磁盘
2. **SWR AK/SK 轮转**：建议季度轮转，更新 `docker-swr-cred` 凭据
3. **DEVOPS_USERS 审计**：定期检查 prod 触发权限，离职人员及时移除
4. **运维仓库分支保护**：GitHub/GitLab 配置 `main` 分支需要 Review 才能合并
5. **容器非 root 运行**：有条件的服务在 `values-prod.yaml` 中加 `securityContext`
6. **资源配额**：在 namespace 级别配置 `ResourceQuota`，防止单服务耗尽集群资源
