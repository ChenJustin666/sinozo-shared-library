# 字段所有权标准（Field Ownership Standard）

> **目的**：明确定义 Helm values 中每个字段属于谁，机器可校验、人可查阅。  
> **状态**：v1.0（运维团队 owner，每季度 review）

---

## 一、设计原则

```
┌─────────────────────────────────────────────────────────────┐
│  原则 1：业务行为开发管，基础设施运维管                      │
│  原则 2：能从业务代码自然得出的字段，开发管                  │
│  原则 3：影响安全/合规/集群稳定性的字段，运维管              │
│  原则 4：环境路由（namespace/registry）属于环境，运维管      │
│  原则 5：字段所属一旦确定，机器强制校验，不靠人工 review     │
└─────────────────────────────────────────────────────────────┘
```

## 三、合并优先级

部署时 Helm 按 `-f` 顺序加载，**后加载的覆盖前加载的**：

```
①  charts/generic-service/values.yaml             (Chart 默认)
       ↓ 被覆盖
②  baselines/_global.yaml                          (全局基线)
       ↓ 被覆盖
③  baselines/{project}/{service}/baseline-{env}.yaml  (服务基线 / 运维管)
       ↓ 被覆盖
④  $WORKSPACE/deploy/values.yaml                   (业务通用 / 开发管)
       ↓ 被覆盖
⑤  $WORKSPACE/deploy/values-{env}.yaml             (业务环境 / 开发管)
       ↓ 被覆盖
⑥  helm --set image.tag=R<commit> ...              (CI 注入)
```

**关键**：运维 baseline 在开发 values 之前加载（顺序③ 在④之前），看似开发能覆盖。但**部署前校验脚本**会拒绝业务 values 中包含运维字段的提交，从源头阻断。

## 四、违反契约的处理

### 4.1 自动校验

每次 Pipeline 部署前自动跑 `automation/values-validate.sh`：

```
✅ 通过：业务 values 中不含运维字段
❌ 拒绝：业务 values 中含禁止字段
   报错示例：
   ┌─────────────────────────────────────────────────────────┐
   │  ❌ Validation failed                                   │
   │  File: deploy/values-prod.yaml                          │
   │  Forbidden fields detected:                             │
   │    - resources.limits.cpu  (managed by Ops)             │
   │    - nodeSelector          (managed by Ops)             │
   │  Action: Remove these fields, or contact Ops team       │
   │          to update baseline at:                         │
   │          k8s-deploy/baselines/adv/ad-gateway/baseline-prod.yaml │
   └─────────────────────────────────────────────────────────┘
```

### 4.2 例外申请

如确需突破 baseline 限制（如临时压测要求 8 核），开发提 MR 到 k8s-deploy 仓库，运维 review。

## 五、字段标准的演进

| 变更类型 | 流程 |
|---------|------|
| 新增运维管字段 | 运维直接加到 baseline，无需通知开发 |
| 新增开发管字段 | 更新本文档 + 更新 `values-validate.sh` 白名单 |
| 字段从开发管 → 运维管 | 先公告 1 周 + 灰度迁移 + 更新文档 |
| 字段从运维管 → 开发管 | 更新文档 + 在 baseline 中删除（让默认值生效） |

## 六、FAQ

**Q1：开发能不能看到 baseline 长什么样？**  
A：可以。k8s-deploy 仓库给开发**只读**权限。开发本地用 `helm-preview.sh adv ad-gateway prod` 即可看到合并后的最终 yaml。

**Q2：开发想本地测试，怎么模拟运维 baseline？**  
A：`git clone --depth 1 k8s-deploy` 后用 `helm template` 即可。不需要镜像仓库、不需要部署权限。

**Q3：开发改了字段不生效？**  
A：99% 是因为该字段在运维管控范围。本地跑 `helm-preview.sh` 会显示该字段最终值的来源（baseline / values）。

**Q4：新加的服务运维忘了创建 baseline？**  
A：Pipeline 第一次部署时检测不到 `baselines/{project}/{svc}/baseline-{env}.yaml` 会自动从模板生成 + 提交 MR + 阻断部署，强制运维 review 后才能继续。

**Q5：能不能批量改 30 个服务的 securityContext？**  
A：放 `baselines/_global.yaml`，全公司服务一次生效。
