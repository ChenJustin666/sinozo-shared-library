# 运维操作指南

> 本文档面向运维人员，涵盖新服务接入、日常部署、回滚、配置变更等操作
> **规模：20+ 开发、20+ 集群、1000+ Pod**

---

## 快速开始

### 核心原则

1. **配置全在 k8s-deploy 仓库**（单仓库管理）
2. **全部接入 Nacos**（统一标准）
3. **自动化脚本初始化**（5 分钟创建新服务）
4. **Git 权限控制**（测试环境自动 merge，生产环境需 approve）

### 仓库结构

```
k8s-deploy/（单个 Git 仓库）
├── charts/generic-service/        # 通用 Helm Chart
├── shared-library/                # Jenkins 共享库
├── projects/                      # 所有项目配置
│   └── {project}/{env}/{service}/values-{env}.yaml
├── automation/                    # 自动化脚本
│   └── init-service.sh           # 快速初始化
└── docs/                          # 文档
```

## 一、新服务接入流程（自动化）

### 1.1 创建 Jenkins Job

```
Jenkins → New Item → Pipeline
名称：{project}-{service}（如 adv-ad-gateway）
```

Pipeline script：

```groovy
@Library('k8s-deploy-lib@main') _

k8sDeploy(
    projectName:  'adv',
    serviceName:  'ad-gateway',
    serviceType:  'java',
    gitUrl:       'http://git.example.com/server/AdGateway.git',
    gitCredId:    'git-adv-cred',
    dockerImage:  'sinozo/ad-gateway',
    dockerCredId: 'docker-swr-cred',
    jdkTool:      'jdk 1.8',
    nacosCredId:  'nacos-adv-test',
)
```

### 1.2 k8sDeploy 完整参数说明

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `projectName` | ✅ | — | 项目名，对应 namespace 前缀 |
| `serviceName` | ✅ | — | 服务名，对应 K8s deployment 名 |
| `serviceType` | ✅ | `java` | `java` / `nodejs` |
| `gitUrl` | ✅ | — | 业务代码 Git 仓库地址 |
| `gitCredId` | ✅ | — | Jenkins Git 凭据 ID |
| `dockerImage` | ✅ | — | 镜像名（不带 registry） |
| `dockerCredId` | ✅ | — | Jenkins Docker 凭据 ID |
| `jdkTool` | — | `jdk 1.8` | Jenkins 全局 JDK 工具名 |
| `mavenTool` | — | — | Jenkins 全局 Maven 工具名 |
| `mavenHome` | — | `/usr/local/maven` | Maven 路径（不用 mavenTool 时） |
| `mavenGoals` | — | `clean package -DskipTests` | Maven 构建命令 |
| `nacosCredId` | — | — | Nacos 凭据（Username/Password） |
| `kubeconfigCredId` | — | `k8s-{project}-{env}` | 集群凭据（默认自动推断） |
| `dockerRegistry` | — | `swr.ap-southeast-3.myhuaweicloud.com` | Docker Registry |
| `defaultBranch` | — | `main` | 默认分支 |
| `subdirectory` | — | — | MonoRepo 子目录 |
| `agent` | — | — | 构建节点标签 |

### 1.3 Job 自动生成的参数

构建时可选择：

| 参数 | 选项 | 说明 |
|------|------|------|
| `DEPLOY_ENV` | test / prod | 部署环境 |
| `GIT_BRANCH` | 分支列表 | 构建分支 |
| `ACTION` | deploy / rollback / restart | 操作类型 |
| `ROLLBACK_REVISION` | 数字 | 回滚版本（0=上一个） |
| `SKIP_HEALTH_CHECK` | true/false | 跳过健康检查 |

### 1.4 给开发 Dockerfile

```bash
# Java 8
cp shared-library/templates/Dockerfile.java8 → 发给开发

# Java 17
cp shared-library/templates/Dockerfile.java17 → 发给开发

# 前端
cp shared-library/templates/Dockerfile.nginx → 发给开发
```

### 1.5 首次构建

```
Jenkins → Job → Build with Parameters
  DEPLOY_ENV: test
  GIT_BRANCH: origin/test
  ACTION: deploy
```

首次构建会：
1. `initDeploy` 自动生成 `projects/adv/test/ad-gateway/values-test.yaml`
2. 提交到 Git
3. **中断部署**，提示检查配置

### 1.6 检查并修改 values 文件

```bash
cd /var/lib/jenkins/workspace/deploy/k8s-deploy
vim projects/adv/test/ad-gateway/values-test.yaml
```

**必须修改的配置：**

```yaml
# 1. Nacos 地址和 namespace
java:
  opts: >-
    -Dspring.cloud.nacos.config.server-addr=实际Nacos地址:8848
    -Dspring.cloud.nacos.config.namespace=实际namespace
    -Dspring.cloud.nacos.discovery.server-addr=实际Nacos地址:8848
    -Dspring.cloud.nacos.discovery.namespace=实际namespace
    -Xms512m -Xmx1024m

# 2. 镜像名确认
image:
  name: sinozo/ad-gateway    # 确认正确

# 3. 端口确认
service:
  port: 8080                  # 确认与应用一致
```

```bash
git add . && git commit -m "config: ad-gateway test 配置" && git push
```

### 1.7 再次构建 → 正式部署

```
Jenkins → Job → Build（再次触发）
→ values 文件存在，正式部署
```

## 二、日常部署操作

### 2.1 正常部署

```
Jenkins → Job → Build with Parameters
  DEPLOY_ENV: test（或 prod）
  GIT_BRANCH: origin/test（或 origin/master）
  ACTION: deploy
```

### 2.2 回滚

```
Jenkins → Job → Build with Parameters
  ACTION: rollback
  ROLLBACK_REVISION: 0        ← 0=上一个版本，1=上上个，以此类推
```

**查看历史版本：**
```bash
helm history {service} -n {namespace} --kubeconfig /path/to/kubeconfig
```

### 2.3 指定镜像部署

如果需要部署特定镜像（不重新构建）：

```bash
# 直接用 helm 命令
cd /var/lib/jenkins/workspace/deploy/k8s-deploy
helm upgrade --install ad-gateway charts/generic-service \
  -f projects/adv/test/ad-gateway/values-test.yaml \
  -n adv-test \
  --set image.tag=R1a2b3c4d5 \
  --kubeconfig /path/to/kubeconfig
```

### 2.4 重启（不重新构建）

```
Jenkins → Job → Build with Parameters
  ACTION: restart
```

等同于 `kubectl rollout restart deployment/{service} -n {namespace}`

### 2.5 扩缩容

修改 values 文件：

```yaml
service:
  replicas: 3    # 改副本数
```

```bash
git push → 重新构建 Job
```

或临时扩容（不改 Git）：

```bash
kubectl scale deployment/ad-gateway --replicas=5 -n adv-prod
# 注意：下次部署会被 values 中的值覆盖
```

## 三、配置变更

### 3.1 修改基础设施配置（CPU/内存/HPA 等）

```bash
vim projects/adv/prod/ad-gateway/values-prod.yaml
# 修改 resources / replicas / hpa 等
git add . && git commit -m "config: ad-gateway 扩容" && git push

# 重新构建 Job 生效
```

### 3.2 开启/关闭功能

在 values 文件中修改对应开关：

```yaml
# 开启监控
monitoring:
  enabled: true
  path: /actuator/prometheus
  port: 8080

# 开启探针
probes:
  enabled: true
  type: http
  path: /actuator/health
  port: 8080

# 开启 HPA
hpa:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  cpuTarget: 70

# 开启 Ingress
ingress:
  enabled: true
  items:
    - host: ad-gateway.example.com
      paths:
        - path: /
          port: 8080
```

### 3.3 修改 Nacos 凭据

```
Jenkins → Credentials → 找到 nacos-adv-prod → Update
修改密码 → 重新部署 Job
```

### 3.4 修改 Docker Registry 凭据

```
Jenkins → Credentials → 找到 docker-swr-cred → Update
修改密码 → 重新部署（会自动更新 pull secret）
```

## 四、生产环境上线

### 4.1 上线前准备

```
□ 测试环境已验证通过
□ 生产 values 文件已创建并配置正确
□ 生产 kubeconfig 凭据已创建（k8s-{project}-prod）
□ 生产 Nacos 凭据已创建（nacos-{project}-prod）
□ 探针和监控已开启
□ 资源限制已设置合理值
□ HPA 已配置（如需要）
```

### 4.2 创建生产 values

```bash
mkdir -p projects/adv/prod/ad-gateway
cp projects/adv/test/ad-gateway/values-test.yaml \
   projects/adv/prod/ad-gateway/values-prod.yaml
```

**生产必须修改的配置：**

```yaml
environment: prod
service:
  namespace: adv-prod
  replicas: 2                    # 至少 2 副本

java:
  opts: >-
    -Dspring.profiles.active=prod
    -Dspring.cloud.nacos.config.server-addr=nacos-prod.internal:8848
    -Dspring.cloud.nacos.config.namespace=ad-gateway-prod
    -Dspring.cloud.nacos.discovery.server-addr=nacos-prod.internal:8848
    -Dspring.cloud.nacos.discovery.namespace=ad-gateway-prod
    -XX:MaxRAMPercentage=72.0 -XX:+UseG1GC

resources:
  enabled: true
  requests: { cpu: 500m, memory: 1Gi }
  limits: { cpu: "2", memory: 4Gi }

# 生产必开
probes:
  enabled: true
  type: http
  path: /actuator/health
  port: 8080

monitoring:
  enabled: true
  path: /actuator/prometheus
  port: 8080

hpa:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  cpuTarget: 70
```

### 4.3 Nacos 凭据处理

如果测试和生产用不同的 Nacos 凭据：

**方式 A：同一个 Job，按环境自动切换**

修改 Jenkinsfile：
```groovy
k8sDeploy(
    // ...
    nacosCredId: 'nacos-adv',    // 测试和生产用同一个 Credential
)
```

**方式 B：创建独立的 prod Job**

```groovy
k8sDeploy(
    // ...
    nacosCredId: 'nacos-adv-prod',    // 生产专用
)
```

### 4.4 构建生产

```
Jenkins → Job → Build with Parameters
  DEPLOY_ENV: prod
  GIT_BRANCH: origin/master
  ACTION: deploy
```

### 4.5 验证

```bash
kubectl get pods -n adv-prod -l app=ad-gateway
kubectl get hpa -n adv-prod
kubectl get pods -n adv-prod -l app=ad-gateway -o yaml | grep prometheus
```

## 五、故障处理

### 5.1 部署失败回滚

```
Jenkins → Job → ACTION: rollback → ROLLBACK_REVISION: 0
```

### 5.2 Pod 起不来

```bash
# 查看 Pod 状态
kubectl get pods -n {namespace} -l app={service}

# 查看事件
kubectl describe pod {pod-name} -n {namespace}

# 查看日志
kubectl logs {pod-name} -n {namespace}

# 常见问题：
# ImagePullBackOff → 检查镜像名/pull secret
# CrashLoopBackOff → 查看日志，可能是配置错误
# Pending → 资源不足，减小 resources 或扩容节点
# OOMKilled → 内存不足，加大 memory limits
```

### 5.3 紧急跳过健康检查

```
Jenkins → Job → SKIP_HEALTH_CHECK: true → Build
```

### 5.4 手动 helm 操作

```bash
cd /var/lib/jenkins/workspace/deploy/k8s-deploy

# 查看当前部署状态
helm list -n adv-prod --kubeconfig /path/to/kubeconfig

# 查看历史
helm history ad-gateway -n adv-prod --kubeconfig /path/to/kubeconfig

# 手动回滚到指定版本
helm rollback ad-gateway 3 -n adv-prod --kubeconfig /path/to/kubeconfig

# 手动卸载（危险！）
helm uninstall ad-gateway -n adv-prod --kubeconfig /path/to/kubeconfig
```

## 六、values.yaml 完整字段参考

```yaml
# ── 项目信息 ──
project: adv                    # 项目名
environment: test               # 环境

# ── 工作负载类型 ──
workloadType: deployment        # deployment / statefulset

# ── 服务配置 ──
service:
  name: ad-gateway
  namespace: adv-test
  port: 8080
  replicas: 1
  type: ClusterIP               # ClusterIP / LoadBalancer / NodePort

# ── 镜像 ──
image:
  registry: swr.ap-southeast-3.myhuaweicloud.com
  name: sinozo/ad-gateway
  tag: latest                   # Jenkins 自动覆盖
  pullSecret: regcred

# ── Java 配置 ──
java:
  enabled: true
  opts: "-Xms512m -Xmx1024m"

# ── 环境变量 ──
env:
  - name: TZ
    value: "Asia/Shanghai"

# ── 资源 ──
resources:
  enabled: true
  requests: { cpu: 256m, memory: 512Mi }
  limits: { cpu: "1", memory: 2Gi }

# ── 探针 ──
probes:
  enabled: false
  type: http                    # http / tcp
  path: /actuator/health
  port: 8080

# ── 监控 ──
monitoring:
  enabled: false
  path: /actuator/prometheus
  port: 8080

# ── HPA ──
hpa:
  enabled: false
  minReplicas: 1
  maxReplicas: 5
  cpuTarget: 70

# ── Ingress ──
ingress:
  enabled: false
  items:
    - host: example.com
      paths:
        - path: /
          port: 8080

# ── PVC ──
pvc:
  enabled: false
  storage: 10Gi
  storageClass: ""

# ── Secret ──
secret:
  enabled: false
  data: {}

# ── ConfigMap ──
configmap:
  enabled: false
  mountPath: /config
  data: {}

# ── PDB ──
pdb:
  enabled: false
  minAvailable: 1

# ── 部署策略 ──
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0

# ── 节点调度 ──
nodeSelector: {}
tolerations: []
affinity: {}

# ── 额外注解/标签 ──
extraAnnotations: {}
extraLabels: {}
```

## 七、多环境管理

### 7.1 环境列表

| 环境 | namespace 格式 | 用途 |
|------|---------------|------|
| dev | `{project}-dev` | 开发联调 |
| test | `{project}-test` | 测试验证 |
| pre | `{project}-pre` | 预发布 |
| prod | `{project}-prod` | 生产 |

### 7.2 扩展 DEPLOY_ENV 选项

修改 `k8sDeploy.groovy` 中的 choices：

```groovy
choice(
    name: 'DEPLOY_ENV',
    choices: ['test', 'dev', 'pre', 'prod'],
    description: '部署环境'
)
```

### 7.3 每个环境需要的凭据

| 环境 | kubeconfig | Nacos |
|------|-----------|-------|
| dev | `k8s-{project}-dev` | `nacos-{project}-dev` |
| test | `k8s-{project}-test` | `nacos-{project}-test` |
| pre | `k8s-{project}-pre` | `nacos-{project}-pre` |
| prod | `k8s-{project}-prod` | `nacos-{project}-prod` |
