> 本文档是开发人员接入 CI/CD 平台的导航入口。  
> 首次接入请先阅读：[容器化与 CI/CD 实战指南](./容器化与CI-CD实战指南.md)（了解为什么要 + 整体流程）

---

## 一、你需要放哪些文件

不论 Java 还是前端，业务仓库只需要放 **3 个文件**：

```
<业务仓库>/
├── Dockerfile               # 镜像构建规则
├── Jenkinsfile              # 流水线配置
└── deploy/
    └── values-test.yaml     # test 环境 K8s 部署参数（开发管）
```

prod 配置由运维在运维仓库维护，开发不用操心。

## 三、整体流程（3 步上线）

```
① 运维执行初始化脚本
   ./automation/init-service.sh <project> <service> [java|nodejs]
   → 输出 Dockerfile + Jenkinsfile + values-test.yaml 模板

② 开发复制到业务仓库，按实际修改后 push
   修改重点：Jenkinsfile 里的 kubeconfigCredId、values-test.yaml 里的端口和 JVM 参数

③ Jenkins 创建 Pipeline Job → 首次触发部署
   test 部署成功后，运维 review prod 配置，触发 prod 部署
```

## 四、字段所有权速查

| 字段 | Owner | 写在哪里 |
|------|-------|---------|
| 镜像 tag / 镜像名 / namespace | CI 自动注入 | ❌ 不用写 |
| registry / pullSecret | 运维全局基线 | ❌ 不用写 |
| 服务端口 / 副本数 / JVM / 探针 | 开发 | `deploy/values-test.yaml` |
| prod 资源 / prod Nacos 地址 | 运维 | 运维仓库 `baselines/projects/` |

**不能写在 values-test.yaml 里的字段**（写了不生效，CI 会警告）：
`image.name` / `image.tag` / `image.registry` / `image.pullSecret` /
`service.namespace` / `service.name` / `project` / `environment`

## 五、Jenkins Job 触发参数

| 参数 | 说明 | 默认 |
|------|------|------|
| `DEPLOY_ENV` | test / prod（Job 名末段自动推断） | 按 Job 名 |
| `GIT_BRANCH` | 分支或 Tag | main |
| `ACTION` | deploy / rollback / restart | deploy |
| `IMAGE_TAG` | 手动指定 tag（留空自动算） | 留空 |
| `SKIP_HEALTH_CHECK` | 跳过健康检查 | false |
