
## 第一部分：Jenkins 环境配置

### 1.1 安装必需插件

进入 Jenkins → Manage Jenkins → Manage Plugins → Available

搜索并安装以下插件：

```
✅ Git Parameter Plugin          # 支持分支选择
✅ Pipeline                       # Pipeline 支持
✅ Kubernetes CLI Plugin          # kubectl 命令支持
✅ Docker Pipeline                # Docker 构建支持
✅ Credentials Binding Plugin     # 凭据绑定
```

安装后重启 Jenkins：
```bash
sudo systemctl restart jenkins
```

### 1.2 配置全局工具

进入 Jenkins → Manage Jenkins → Global Tool Configuration

#### 配置 JDK

```
Name: jdk 1.8
JAVA_HOME: /usr/lib/jvm/java-8-openjdk-amd64

Name: jdk 17
JAVA_HOME: /usr/lib/jvm/java-17-openjdk-amd64
```

#### 配置 Maven（可选）

```
Name: maven 3.8
Install automatically: ✅
Version: 3.8.6
```

或使用已安装的 Maven：
```
Name: maven 3.8
MAVEN_HOME: /usr/local/maven
```

### 1.3 准备 k8s-deploy 仓库

在 Jenkins 节点上克隆配置仓库：

```bash
# 切换到 jenkins 用户
sudo su - jenkins

# 创建部署目录
mkdir -p /var/lib/jenkins/workspace/deploy
cd /var/lib/jenkins/workspace/deploy

# 克隆 k8s-deploy 仓库
git clone http://git.example.com/ops/k8s-deploy.git

# 验证
ls -la k8s-deploy/
# 应该看到：charts/ shared-library/ projects/ docs/ 等目录
```

## 第二部分：配置 Shared Library

### 2.1 上传 Shared Library 到 Git

确保 `shared-library/` 目录已经推送到 Git 仓库：

```bash
cd k8s-deploy
git add shared-library/
git commit -m "feat: 添加 Jenkins Shared Library"
git push origin main
```

### 2.2 在 Jenkins 中配置 Shared Library

进入 Jenkins → Manage Jenkins → Configure System → Global Pipeline Libraries

点击 "Add" 添加新库：

```
Name: k8s-deploy-lib
Default version: main
Load implicitly: ❌ (不勾选)

Retrieval method: Modern SCM
  Source Code Management: Git
    Project Repository: http://git.example.com/ops/k8s-deploy.git
    Credentials: (选择 Git 凭据)
    
Library Path: shared-library
```

**重要**：Library Path 必须填写 `shared-library`，因为我们的库在仓库的 `shared-library/` 子目录下。

点击 "Save" 保存。

### 2.3 验证 Shared Library

创建一个测试 Pipeline Job：

```groovy
@Library('k8s-deploy-lib@main') _

pipeline {
    agent any
    stages {
        stage('Test') {
            steps {
                script {
                    echo "✅ Shared Library 加载成功！"
                }
            }
        }
    }
}
```

运行后应该看到 "✅ Shared Library 加载成功！"

## 第三部分：准备凭据

### 3.1 Git 凭据

进入 Jenkins → Manage Jenkins → Manage Credentials → (global) → Add Credentials

```
Kind: Username with password
Scope: Global
Username: <Git 用户名>
Password: <Git 密码或 Token>
ID: git-adv-cred
Description: Git 仓库凭据 - adv 项目
```

### 3.2 Docker Registry 凭据

```
Kind: Username with password
Scope: Global
Username: <Docker Registry 用户名>
Password: <Docker Registry 密码>
ID: docker-swr-cred
Description: 华为云 SWR 镜像仓库凭据
```

### 3.3 Kubernetes 集群凭据

准备 kubeconfig 文件，然后上传：

```
Kind: Secret file
Scope: Global
File: <上传 kubeconfig 文件>
ID: k8s-adv-test
Description: K8s 集群 - adv 测试环境
```

重复此步骤为每个环境创建凭据：
- `k8s-adv-test` - 测试环境
- `k8s-adv-prod` - 生产环境

**命名规范**：`k8s-{项目名}-{环境}`，这样 Shared Library 会自动推断。

### 3.4 Nacos 凭据（可选）

如果需要在部署时动态注入 Nacos 密码：

```
Kind: Username with password
Scope: Global
Username: nacos
Password: <Nacos 密码>
ID: nacos-adv-cred
Description: Nacos 配置中心凭据 - adv 项目
```

### 3.5 凭据清单总结

| 凭据 ID | 类型 | 用途 |
|---------|------|------|
| `git-adv-cred` | Username/Password | 拉取业务代码 |
| `docker-swr-cred` | Username/Password | 推送 Docker 镜像 |
| `k8s-adv-test` | Secret file | 连接测试集群 |
| `k8s-adv-prod` | Secret file | 连接生产集群 |
| `nacos-adv-cred` | Username/Password | Nacos 密码注入（可选） |

## 第四部分：新服务接入实战

以接入一个名为 `ad-gateway` 的 Java 服务为例。

### 4.1 运维：初始化配置

```bash
cd /var/lib/jenkins/workspace/deploy/k8s-deploy

# 运行初始化脚本
./automation/init-service.sh adv ad-gateway java

# 输出：
# 🚀 初始化服务: adv/ad-gateway (java)
# 📁 创建配置目录...
#   ✓ projects/adv/dev/ad-gateway
#   ✓ projects/adv/test/ad-gateway
#   ✓ projects/adv/prod/ad-gateway
# 📋 复制配置模板...
#   ✓ projects/adv/test/ad-gateway/values-test.yaml
#   ✓ projects/adv/prod/ad-gateway/values-prod.yaml
# 📦 生成业务仓库文件...
#   ✓ /tmp/ad-gateway-init-XXXXXX/Dockerfile
#   ✓ /tmp/ad-gateway-init-XXXXXX/Jenkinsfile
```

### 4.2 运维：检查并修改配置

编辑生成的配置文件：

```bash
vim projects/adv/test/ad-gateway/values-test.yaml
```

重点检查以下内容：

```yaml
# 1. 服务基本信息
service:
  name: ad-gateway
  namespace: adv-test
  port: 8080              # 确认端口正确

# 2. 镜像配置
image:
  registry: swr.ap-southeast-3.myhuaweicloud.com
  name: sinozo-test/ad-gateway    # 确认镜像名称
  tag: latest

# 3. Java 配置（重点）
java:
  enabled: true
  opts: >-
    -Dspring.application.name=ad-gateway
    -Dspring.profiles.active=test
    -Dspring.cloud.nacos.config.server-addr=nacos.internal:8848
    -Dspring.cloud.nacos.config.namespace=ad-gateway-test
    -Dspring.cloud.nacos.config.username=nacos
    -Dspring.cloud.nacos.config.password=nacos123    # 修改为实际密码
    -Xms512m -Xmx1024m                               # 调整内存

# 4. 资源配置
resources:
  enabled: true
  limits:
    cpu: "1"
    memory: 2Gi
  requests:
    cpu: 256m
    memory: 512Mi
```

**提示**：关于密码管理，建议使用 K8s Secret，详见 [05-进阶配置-Webhook与Secret管理.md](05-进阶配置-Webhook与Secret管理.md)

### 4.3 运维：提交配置

```bash
git add projects/adv/
git commit -m "feat: 添加 ad-gateway 服务配置"
git push origin main
```

### 4.4 开发：接入业务代码

将生成的文件复制到业务仓库：

```bash
# 查看生成的文件位置（在初始化脚本输出中）
ls /tmp/ad-gateway-init-XXXXXX/

# 复制到业务仓库
cp /tmp/ad-gateway-init-XXXXXX/Dockerfile ~/projects/ad-gateway/
cp /tmp/ad-gateway-init-XXXXXX/Jenkinsfile ~/projects/ad-gateway/

# 提交到 Git
cd ~/projects/ad-gateway
git add Dockerfile Jenkinsfile
git commit -m "feat: 添加容器化配置"
git push origin main
```

检查 Jenkinsfile 内容：

```groovy
@Library('k8s-deploy-lib@main') _

k8sDeploy(
    projectName:  'adv',
    serviceName:  'ad-gateway',
    serviceType:  'java',
    gitUrl:       'http://git.example.com/server/AdGateway.git',
    gitCredId:    'git-adv-cred',
    dockerImage:  'sinozo/ad-gateway',
    dockerCredId: 'docker-swr-cred',
    jdkTool:      'jdk 1.8',
)
```

## 第五部分：首次部署

### 5.1 创建 Jenkins Job

#### 测试环境 Job

进入 Jenkins → New Item

```
Item name: ad-gateway-test
Type: Pipeline
```

配置：

**General**
```
Description: ad-gateway 测试环境部署
```

**Build Triggers**
```
(可选) Poll SCM: H/5 * * * *    # 每 5 分钟检查一次代码变更
```

**Pipeline**
```
Definition: Pipeline script from SCM
  SCM: Git
    Repository URL: http://git.example.com/server/AdGateway.git
    Credentials: git-adv-cred
    Branch Specifier: */main
  Script Path: Jenkinsfile
```

**Parameters**（会自动从 Jenkinsfile 读取，但可以设置默认值）
```
DEPLOY_ENV: test (默认值)
```

点击 "Save" 保存。

#### 生产环境 Job

重复上述步骤，创建 `ad-gateway-prod`，唯一区别：
```
DEPLOY_ENV: prod (默认值)
```

### 5.2 首次构建（测试环境）

进入 Jenkins → ad-gateway-test → Build with Parameters

```
DEPLOY_ENV: test
GIT_BRANCH: main
ACTION: deploy
ROLLBACK_REVISION: 0
SKIP_HEALTH_CHECK: false
```

点击 "Build"。

### 5.3 查看构建日志

构建过程会经历以下阶段：

```
Stage 1: 权限检查
  ✅ 测试环境，无需审批

Stage 2: 初始化
  📋 检查 k8s-deploy 仓库
  📋 拉取最新配置
  ✅ values-test.yaml 已存在

Stage 3: 构建镜像
  📦 Checkout 代码: main 分支
  🔨 Maven 构建: clean package -DskipTests
  🐳 Docker 构建: ad-gateway:R<commit-hash>
  📤 推送镜像到 SWR

Stage 4: 部署到 K8s
  ⚙️  Helm upgrade --install ad-gateway
  ⏳ 等待 Pod 就绪...
  ✅ 部署成功！
```

### 5.4 验证部署

```bash
# 查看 Pod 状态
kubectl get pods -n adv-test

# 查看服务
kubectl get svc -n adv-test

# 查看日志
kubectl logs -f deployment/ad-gateway -n adv-test

# 查看 Helm 发布
helm list -n adv-test
```
