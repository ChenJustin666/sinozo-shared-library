# 前端服务接入指南

> 适用于：React / Vue / 静态页面（Node.js 多阶段 Docker 构建）  
> 配套阅读：[变量外置规范](./变量外置规范.md)

---

## 一、前端构建机制说明

前端与 Java 不同，**不需要 Jenkins 节点安装 Node.js**。

使用 Docker 多阶段构建：
```
第一阶段（node 镜像）：npm install + npm run build → 产出 dist/
第二阶段（nginx 镜像）：复制 dist/ 到 Nginx → 运行时只有 Nginx
```

Jenkins 只需要有 Docker 命令即可，Node 版本由 Dockerfile 的 FROM 控制。

## 二、Dockerfile

### 2.1 使用平台模板（推荐，快速上手）

直接复制 `shared-library/templates/Dockerfile.nginx` 到业务仓库根目录：

```dockerfile
FROM nginx:1.25-alpine

# 内置 Nginx 配置（SPA 路由支持 + Gzip + 静态资源缓存）
COPY <<'NGINX_CONF' /etc/nginx/conf.d/default.conf
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript;

    # SPA 路由（React Router / Vue Router）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 健康检查接口
    location /health {
        access_log off;
        return 200 "OK\n";
        add_header Content-Type text/plain;
    }
}
NGINX_CONF

COPY dist/ /usr/share/nginx/html/
RUN chown -R nginx:nginx /usr/share/nginx/html
USER nginx
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**要求**：`npm run build` 输出到 `dist/` 目录。如果你的项目输出到 `build/`，把 `COPY dist/` 改成 `COPY build/`。

### 2.2 多阶段构建（包含 npm build，适合自定义 Node 版本）

```dockerfile
# 第一阶段：构建
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci                    # 用 ci 而不是 install，保证 lock 文件一致
COPY . .
RUN npm run build

# 第二阶段：运行
FROM nginx:1.25-alpine
COPY --from=builder /app/dist /usr/share/nginx/html/
COPY nginx.conf /etc/nginx/conf.d/default.conf   # 如需自定义 nginx 配置
RUN chown -R nginx:nginx /usr/share/nginx/html
USER nginx
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

## 三、Jenkinsfile 配置

```groovy
@Library('k8s-deploy-lib@main') _

k8sDeploy(
    // ── 必填（改成实际值）──
    projectName:  'adv',
    serviceName:  'ad-admin-fe',    // 服务名（小写）
    serviceType:  'nodejs',         // 前端统一写 nodejs
    dockerImage:  'ad-admin-fe',    // SWR 镜像名（不含 project 前缀）
    dockerCredId: 'docker-swr-cred',

    // ── K8s 集群凭据（运维提供）──
    kubeconfigCredId: [
        test: 'test-k8s-cluster',
        prod: 'prod-k8s-cluster',
    ],

    // ── 以下可选 ──
    // defaultBranch: 'main',
    // agent:         'docker-build',
    // subdirectory:  '',
)
```

前端不需要 `jdkTool` / `mavenTool` / `nacosCredId`，配置比 Java 简单很多。

## 四、deploy/values-test.yaml 配置

### 4.1 最小配置

```yaml
# deploy/values-test.yaml
service:
  port: 80          # Nginx 监听 80
  replicas: 1

resources:
  enabled: true
  requests:
    cpu: 50m
    memory: 64Mi
  limits:
    cpu: 200m
    memory: 256Mi
```

### 4.2 带 Ingress 域名

```yaml
service:
  port: 80
  replicas: 1

resources:
  enabled: true
  requests:
    cpu: 50m
    memory: 64Mi
  limits:
    cpu: 200m
    memory: 256Mi

# 健康探针（Nginx 模板自带 /health，可直接开）
probes:
  enabled: true
  type: http
  path: /health
  port: 80
  liveness:
    periodSeconds: 30
    failureThreshold: 3
  readiness:
    periodSeconds: 10
    failureThreshold: 3
  startup:
    periodSeconds: 10
    failureThreshold: 12    # 2 分钟启动窗口

# 对外暴露域名
ingress:
  enabled: true
  items:
    - host: ad-admin-test.example.com
      paths:
        - path: /
          pathType: Prefix
      tls: false
```

### 4.3 带运行时环境变量（推荐方案）

如果前端采用运行时注入配置（参考[变量外置规范](./变量外置规范.md)），在 `env` 里写：

```yaml
service:
  port: 80
  replicas: 1

resources:
  enabled: true
  requests:
    cpu: 50m
    memory: 64Mi
  limits:
    cpu: 200m
    memory: 256Mi

# 运行时注入到容器的环境变量
env:
  - name: API_BASE_URL
    value: https://api-test.internal
  - name: APP_ENV
    value: test

probes:
  enabled: true
  type: http
  path: /health
  port: 80
  liveness:
    periodSeconds: 30
    failureThreshold: 3
  readiness:
    periodSeconds: 10
    failureThreshold: 3
  startup:
    periodSeconds: 10
    failureThreshold: 12

ingress:
  enabled: true
  items:
    - host: ad-admin-test.example.com
      paths:
        - path: /
          pathType: Prefix
      tls: false
```

### 4.4 双 Ingress（前端 + API 代理）

适合前端需要通过 Ingress 转发 API 请求到后端，规避跨域：

```yaml
service:
  port: 80
  replicas: 1

resources:
  enabled: true
  requests:
    cpu: 50m
    memory: 64Mi
  limits:
    cpu: 200m
    memory: 256Mi

ingress:
  enabled: true
  items:
    # Ingress 1：API 路径代理到后端网关
    - name: api
      className: alb
      annotations:
        alb.ingress.kubernetes.io/use-regex: "true"
        alb.ingress.kubernetes.io/rewrite-target: /${2}
      hosts:
        - host: ad-admin-test.example.com
          paths:
            - path: /api(/|$)(.*)
              pathType: Prefix
              backend:
                service: ad-gateway-svc    # 后端网关 Service 名
                port: 8080
      tls:
        enabled: false

    # Ingress 2：其余路径走前端静态资源
    - name: web
      className: alb
      hosts:
        - host: ad-admin-test.example.com
          paths:
            - path: /
              pathType: Prefix
      tls:
        enabled: false
```

## 五、前端 Nginx 配置说明

平台模板内置的 Nginx 配置已满足大多数场景：

| 功能 | 说明 |
|------|------|
| SPA 路由 | `try_files $uri /index.html`，React Router / Vue Router 正常工作 |
| Gzip 压缩 | 自动对 JS / CSS / JSON 压缩 |
| 静态资源缓存 | `.js/.css/.png` 等设 1 年强缓存 |
| 健康检查 | `/health` 返回 200，探针可直接用 |

**需要自定义 Nginx 配置时**，在业务仓库放 `nginx.conf`，Dockerfile 里 `COPY nginx.conf /etc/nginx/conf.d/default.conf`。

常见自定义场景：

```nginx
# 前端代理到后端（避免跨域）
location /api/ {
    proxy_pass http://ad-gateway-svc:8080/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

## 七、常见问题

### Q1: 白屏，刷新页面 404

SPA 路由问题。检查 Nginx 配置是否有 `try_files $uri /index.html`。使用平台模板 Dockerfile 默认已有，自定义 nginx.conf 时需手动加。

### Q2: 静态资源 404

`npm run build` 输出目录不是 `dist/`（有的项目用 `build/` 或 `public/`）。

修改 Dockerfile：
```dockerfile
COPY dist/ /usr/share/nginx/html/
# 改成实际目录，如：
COPY build/ /usr/share/nginx/html/
```

### Q3: API 请求跨域

两种解法：
1. **Nginx 反代**：在 nginx.conf 里加 `proxy_pass`（见第五章）
2. **双 Ingress**：Ingress 层做路径转发（见 4.4 节）

不推荐在前端代码里改 CORS 设置，应从部署层解决。

### Q4: 想用特定 Node.js 版本构建

修改 Dockerfile 多阶段构建的第一阶段 FROM：

```dockerfile
FROM node:16-alpine AS builder   # 改成需要的版本
```

平台模板（`Dockerfile.nginx`）不包含 Node 构建阶段，需要换成自定义 Dockerfile。

### Q5: 环境变量如何传入前端

参考 [变量外置规范 → 前端变量外置方案](./变量外置规范.md#二前端变量外置)。

两种主流方案：
- **构建时注入**：Dockerfile ARG 传入，打包进静态文件，镜像与环境绑定
- **运行时注入**（推荐）：Nginx 启动时生成 `config.js`，values 里写 `env` 控制，一个镜像跑所有环境
