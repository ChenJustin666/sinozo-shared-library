# Node.js + PM2 前端服务接入指南

本文针对当前由 Node.js 和 PM2 启动的前端、SSR 或 API 服务。纯静态 React/Vue 可以自带 Nginx Dockerfile，但不使用这里的 PM2 默认端口。完整部署规范见 [Kustomize 部署方案](./Kustomize.md)。

## 1. 应用约定

业务必须提交 `package-lock.json`，并在 `package.json` 提供生产启动脚本：

```json
{
  "scripts": {
    "build": "next build",
    "start": "next start -p ${PORT:-8080}"
  }
}
```

应用必须监听 `0.0.0.0`。不要使用只监听 localhost 的开发服务器，也不要在容器内运行 `pm2 daemon` 或 `pm2 start -i max`；平台镜像使用 `pm2-runtime` 保持前台和转发 SIGTERM，扩容交给 Kubernetes。

## 2. Dockerfile

默认使用 [Dockerfile.nodejs-pm2](../shared-library/templates/Dockerfile.nodejs-pm2)：构建阶段执行 `npm ci` 和可选的 `npm run build`，运行阶段执行：

```text
pm2-runtime npm -- start
```

Node 版本默认为 20，和 Java 统一使用默认端口 8080，运行用户 UID/GID 为 1000。项目如依赖原生模块，应在 Dockerfile 中补齐编译与运行库，不能只在 Jenkins 节点安装依赖。

## 3. Kustomize 配置

```bash
./automation/init-service.sh adv ad-admin nodejs
```

生成的 base 包含 Deployment、Service、TCP 探针、资源限制、`regcred` 和非 root 安全上下文。测试环境变量写入 `deploy/kustomize/overlays/test/deployment-patch.yaml`：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ad-admin
spec:
  template:
    spec:
      containers:
        - name: app
          env:
            - name: NODE_ENV
              value: test
            - name: PORT
              value: "8080"
            - name: API_BASE_URL
              value: https://api-test.internal
```

若有 `/health`，可以把 TCP readiness/liveness 改成 HTTP；存量应用端口不是 8080 时，初始化脚本传入实际端口，或同时修改 `containerPort`、Service、`PORT` 和探针。测试 overlay 默认包含 ALB Ingress，修改 `host` 后提交；生产 Ingress 在业务仓库 prod overlay 管理，并通过受保护 `PROD_BRANCH` 合并。

## 4. Jenkinsfile

```groovy
@Library('k8s-deploy-lib@main') _
k8sDeploy(
    projectName:  'adv',
    serviceName:  'ad-admin',
    serviceType:  'nodejs',
    dockerImage:  'ad-admin',
    dockerCredId: 'docker-swr-cred',
)
```

## 5. 纯静态前端

纯静态前端可继续使用业务自带的 Nginx 多阶段 Dockerfile，并把 Kustomize base 调整为容器端口和 Service 端口 80。静态站点环境变量不会因为写进 Pod `env` 自动进入浏览器 bundle；应在容器启动时生成 `config.js`，或者采用相对 API 路径。PM2/SSR 应用则可以直接读取 Pod 环境变量。

## 6. 常见问题

- PM2 启动后立即退出：检查 `npm start` 是否持续前台运行，以及生产依赖是否被误放在 `devDependencies`。
- Pod 正常但 Service 不通：检查应用监听 `0.0.0.0`、端口和 selector。
- 页面可开但 API 错误：检查 overlay 的运行时 API 地址或 Ingress 路由。
- 构建阶段失败：确保 lockfile 与 `package.json` 同步，先在相同 Node 20 镜像中验证 `npm ci`。
